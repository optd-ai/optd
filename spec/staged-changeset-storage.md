# Immutable Staged Changeset Storage

## Decision

A successful stage persists immutable execution evidence and a separately
mutable/append-only lifecycle. Commit applies only the persisted canonical
operation graph. No mutable proposal/request JSON is the source of truth.

Postgres UUID columns use RFC 9562 UUIDv7 values generated by the server.

## Core tables

```text
staged_changesets                         # immutable; no UPDATE/DELETE
- id                         uuid primary key
- schema_version             integer not null       # 1
- source_kind                text not null          # direct | action | seed
- source_identity_json       jsonb not null          # safe structured identity
- created_auth_context_id    uuid not null
- operation_graph_digest     text not null           # sha256:<hex>
- stage_digest               text not null           # sha256:<hex>
- canonical_graph_json       jsonb not null
- warnings_json              jsonb not null
- planned_events_json        jsonb not null
- planned_deliveries_json    jsonb not null
- created_at                 timestamptz not null

staged_changeset_operations               # immutable
- stage_id                    uuid not null
- ordinal                     integer not null
- operation_id                uuid not null
- project_id                  uuid not null
- pack_revision_id            uuid not null
- resource_revision_id        uuid not null
- operation_kind              text not null
- object_id                   uuid null
- canonical_operation_json    jsonb not null
primary key(stage_id, ordinal)
unique(stage_id, operation_id)

staged_changeset_dependencies             # immutable
- stage_id                    uuid not null
- ordinal                     integer not null
- dependency_kind             text not null
  # project | pack_revision | object_version | relationship | uniqueness | policy
- project_id                  uuid null
- pack_revision_id            uuid null
- resource_revision_id        uuid null
- object_id                   uuid null
- expected_version_id         uuid null
- dependency_json             jsonb not null
primary key(stage_id, ordinal)

staged_hook_executions                    # immutable
- id                          uuid primary key
- stage_id                    uuid not null
- ordinal                     integer not null
- phase                       text not null
- pack_revision_id            uuid not null
- hook_revision_id            uuid not null
- input_digest                text not null
- output_digest               text not null
- output_json                 jsonb not null
- stderr_text                 text not null
- duration_ms                 bigint not null

staged_policy_decisions                   # immutable
- id                          uuid primary key
- stage_id                    uuid not null
- ordinal                     integer not null
- project_id                  uuid not null
- action                      text not null
- resource_identity           text not null
- decision_json               jsonb not null
unique(stage_id, ordinal)

- id                          uuid primary key

```

The normalized operation/dependency rows are the commit lock/revalidation input.
`canonical_graph_json` is the RFC 8785 graph representation returned to clients;
the two forms are written in one transaction and checked against the same
digest.

## Lifecycle and decisions

```text
staged_changeset_lifecycle                # coordination row locked first
- stage_id                    uuid primary key
- status                      text not null
  # ready | awaiting_approval | rejected | cancelled | committed
- version                     bigint not null
- cancelled_auth_context_id   uuid null
- cancelled_at                timestamptz null
- committed_at                timestamptz null

staged_approval_decisions                 # append-only
- id                          uuid primary key
- stage_id                    uuid not null
- requirement_id              uuid not null
- principal_id                uuid not null
- decision                    text not null          # approve | reject
- reason                      text null
- decided_auth_context_id     uuid not null
- decided_at                  timestamptz not null
unique(requirement_id, principal_id)

changeset_commits                         # append-only, exactly once per stage
- id                          uuid primary key
- stage_id                    uuid not null unique
- committed_auth_context_id   uuid not null
- authorization_cutoff_at     timestamptz not null
- operation_graph_digest      text not null
- committed_at                timestamptz not null
```

Approval decisions follow [Changeset Approval Contract](changeset-approvals.md)
and never update operation/evidence rows. The lifecycle row is coordination
metadata, not part of the immutable stage digest. Stage,
approval/rejection, cancellation, and commit transitions are audited.

## Atomic stage persistence

Stage parsing, trusted hooks, canonicalization, schema/constraint/policy checks,
and graph digesting happen before persistence. On any failure, none of the above
stage rows exist. On success, all immutable rows, approval requirements, and the
initial lifecycle row are inserted in one transaction.

Database protections must reject UPDATE/DELETE on immutable and append-only
rows through the application role. Development migrations may invalidate old
pre-auth data; no compatibility layer or mutable-record backfill is required.

## Representation

Stage creation and inspection return the same `changeset.stage.v1` data object:

```text
id, schema_version, source, status, lifecycle_version,
created_at, created_auth_context_id,
operation_graph_digest, stage_digest,
projects[], pack_revisions[], operations[], dependencies[],
hook_executions[], policy_decisions[], warnings[],
approval_requirements[], approval_decisions[], planned_events[],
planned_deliveries[], commit|null, cancellation|null
```

Arrays use the canonical ordinals stored above. Later lifecycle/decision/commit
facts are outside `stage_digest`. The stage digest is RFC 8785/SHA-256 over a
versioned object containing operation graph digest, canonical dependencies,
pinned project/pack/resource/hook/policy revisions and security digests, staged
policy decisions, required capabilities/effects, approval requirements, and
planned event/delivery
identities. It excludes auth/request/timestamps, warnings, stderr/durations, and
later lifecycle facts. `operation_graph_digest` covers exactly the normalized
operation graph specified in `changeset-operation-schema.md`.

Secrets, secret values, bearer credentials, initiating tokens, request headers,
process evidence, and unredacted hook environment are never persisted in this
representation. Hook secret evidence stores IDs/versions/digests required by the
secret-grant contract, not plaintext.

## Commit read set

Commit locks `staged_changeset_lifecycle` first by stage ID, reads immutable
operations/dependencies by ordinal, verifies the stored graph digest, then
follows the canonical locking and one-statement authorization cutoff in
`commit-revalidation.md`. It does not read source action input to regenerate
operations and never executes synchronous hooks.

A repeated commit of an already committed stage returns the existing
`changeset_commits` result. A unique violation on `changeset_commits.stage_id`
is resolved by loading that result, never by applying operations twice.
